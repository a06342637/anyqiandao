# any签到助手 v0.6.1

私有部署的 AnyRouter 凭证提取、账号检测与自动签到工作空间。React / TypeScript / Vite 前端，FastAPI / Playwright / SQLite 后端。

v0.6.1 起，未登录仅显示登录页；公网管理访问必须使用 HTTPS，无域名时通过 SSH 隧道访问。备份和恢复无需额外密码：手动导出 JSON，远程备份生成 ZIP。升级前请阅读 [安全与隐私说明](docs/安全与隐私.md)。

## 功能

- 账号添加、CSV 分块导入、加密保存密码与凭证、编辑备注和账号密码、拖拽排序及分页。
- 批量仅重提已失效账号，或检测时自动修复失效 Cookie；网络错误和验证码不会触发重登。所有手动、批量、定时任务共用一个执行名额，当前任务及浏览器清理结束后才开始下一个。
- 独立执行队列支持暂停、刷新、筛选、分页、跨页多选停止并删除，以及清理已结束任务；内存不足时等待释放后自动继续，避免小服务器同时启动多个浏览器。
- 已添加账号不可重复添加，批量导入自动跳过且不覆盖密码。运行日志标明直连或每次实际选择的代理。
- 账号列表从序号、账号开始排列，桌面表格与平板/手机卡片适配；前后余额、期间消耗和网站回执在账号明细日志查看，复制与账号操作分组排列。
- 单个/批量导入 session 与 api_user，支持分隔文本及 GitHub 配置 JSON；自动标记为 Session 账号，无需密码，失效后保留并等待手动更新，不自动登录。
- 每个账号独立加载网站数据看板和 API 令牌；查看用量、趋势、模型分布、令牌额度/有效期/限制，复制网站已有令牌，不创建或修改令牌。
- 运行/账号日志、队列历史和签到明细分别设置保留天数与统一清理间隔；日志与签到明细支持多选或按截止时间清理，等待/运行任务及相关记录受保护。
- 打开页面或重新登录默认进入仪表盘；账号列表的「余额」只显示当前金额与北京时间「上次签到」，具体操作结果保留在明细日志。
- 按北京时间每日 00:00 划分签到日，以「余额变化＋期间消耗」核对固定 $25 到账；消费不取消当日签到依据，其他金额增加不直接视为签到。
- 今天 / 近 7 天 / 近 30 天统计同样按北京时间划日，不随界面显示时区改变；领取前在同一浏览器会话中复核最新余额，已观察到今日到账就不再发送领取请求。
- 余额或消耗暂时读不全时保留上一份完整观察，不把不同请求的值混算，也不清空已知余额；账号列表和仪表盘明确区分加载中、读取失败与真实空列表。
- 恢复备份按最新余额观察时间防止倒退，同时合并同一账号同一天的确认依据；较新但未确认的快照不会抹掉已签到依据，旧回执可以补齐确认但不覆盖较新余额。
- 按今天、近 7 天、近 30 天统计签到新增；新版确认成功每次固定计 $25，邀请划转不混入奖励，已签过和待确认不重复累计，旧记录保留原统计口径。
- 队列、账号、签到计划、统计明细与分类日志分页，每页 5 / 10 / 15 / 20 / 30 / 50 条。
- 底部居中显示真实任务结果；刷新等待接口返回，不以固定延时冒充成功。
- HTTP / SOCKS5 / SSH 代理，指纹确认、代理连通性检测和明确的直连模式。
- 设置一键备份与合并恢复账号、密码、凭证、代理、计划、备注及签到统计。
- 在线版本检测、源码校验、完整备份、健康检查与失败回滚。默认更新源为 [a06342637/anyqiandao](https://github.com/a06342637/anyqiandao) 的 GitHub Releases，支持自定义仓库。
- 远程自动备份支持阿里云 OSS（V4 签名）与 SSH / SFTP（密码或私钥），按天/小时定时执行、停机补做一次、手动备份、连接测试、目录浏览及独立保留份数。备份日志统一筛选与自动清理。
- 应用数据 JSON/ZIP 可直接恢复，无需备份或恢复密码；完整 ZIP 额外包含程序源码、数据库快照和原密钥。远程存储凭证加密保存，备份包不包含远程存储凭证或运行日志。
- 设置中自定义网站名称与图标文字，左上角、登录页、浏览器标签同步更新，外观设置随备份恢复。
- 统计从同一数据库快照生成；中断或超时单列为待确认，未来时间记录不提前累计，小额余额保留原始精度后汇总。

## 新机器部署教程

下面的命令在**新服务器的 SSH 终端**执行。推荐 Ubuntu 22.04+ 或 Debian 12+，推荐 2GB 内存、6GB 可用磁盘空间；1GB 内存服务器请配置至少 1GB Swap 并保留其他服务所需空间，能够访问 GitHub、Docker 和系统软件源。服务器上的 Docker Engine、Compose、Python 3 及应用运行依赖由部署脚本安装；自己的电脑不需要安装开发环境。

### 1. 登录服务器，进入 root

先使用 SSH 客户端连接自己的服务器。例如，服务器登录用户是 `ubuntu`：

```bash
ssh ubuntu@你的服务器IP
```

登录成功后执行：

```bash
sudo -i
```

如果已经以 root 登录，可直接进入下一步。以下命令都按 root 终端编写。

### 2. 下载项目并启动部署

先安装下载源码需要的 Git：

```bash
apt-get update
apt-get install -y git ca-certificates
```

再下载项目并启动安装：

```bash
git clone --depth 1 https://github.com/a06342637/anyqiandao.git /opt/any-signin-assistant && \
cd /opt/any-signin-assistant && \
bash scripts/deploy.sh
```

`/opt/any-signin-assistant` 是本教程使用的部署目录。以上命令用于首次部署；如果该目录已经有项目，请按下方“以后怎么更新”操作，不要删除旧目录重新安装。

### 3. 按提示填写端口、用户名和密码

| 安装提示 | 直接按回车 | 自定义示例 |
| --- | --- | --- |
| 应用端口 | 随机选择一个空闲端口 | `18780`，方便提前配置安全组 |
| 管理员用户名 | `admin` | 自己的管理账号 |
| 管理员密码 | 自动生成随机强密码 | 5–1024 位密码，输入时不回显 |

然后脚本会下载运行环境、构建镜像、初始化数据库与密钥、启动应用并安装在线更新执行器。首次构建可能需要几分钟至十几分钟，请等待终端显示“已部署”。

默认成功后输出本机访问地址，例如 `http://127.0.0.1:18780`，仅监听服务器本机。如果端口选择了回车，使用终端实际输出的端口。公网直访 HTTP 不接受登录，请使用下方 SSH 隧道或 HTTPS。

### 4. 通过 SSH 隧道安全登录

默认无域名部署无需向公网开放应用端口。在**自己电脑的新终端**建立 SSH 隧道，以下假设第 3 步选了 `18780`：

```bash
ssh -N -L 18780:127.0.0.1:18780 ubuntu@你的服务器IP
```

保持该终端运行，在自己电脑浏览器打开 `http://127.0.0.1:18780`。如果安装时选择了其他端口，把隧道两端端口和浏览器地址一起改成实际值；SSH 登录用户按自己的服务器填写。服务器只需开放 SSH 端口。

通过隧道打开页面后，使用第 3 步设置的管理员账号和密码登录。忘记刚才随机生成的密码时，在服务器执行：

```bash
cat /opt/any-signin-assistant/部署信息.txt
```

此文件包含初始登录信息，请只在自己的终端查看。以后通过密码重置功能改过密码时，以新密码为准，初始文件不会自动改写。

查看当前访问地址和端口：

```bash
grep -E '^APP_(PUBLIC_URL|PORT)=' /opt/any-signin-assistant/.env
```

远程传输由 SSH 加密；如需直接从公网浏览器访问，请配置下面的 HTTPS 入口。

### 可选：首次部署就使用域名和 HTTPS

先将自己的域名 A 记录解析到服务器 IPv4，放行 TCP 80/443，并确认这两个端口没有被其他服务占用。在第 2 步下载源码后，将部署命令换成：

```bash
cd /opt/any-signin-assistant
bash scripts/deploy.sh https://你的域名
```

内置 Caddy 会申请并自动续期证书，访问地址是 `https://你的域名`，应用端口只绑定本机。域名不要带路径，HTTPS 模式下应用端口不要选 80 或 443。

该方式用于**首次安装时选择 HTTPS**。已有 IP 部署再次运行脚本会保留原配置；如需改用域名或自己的反向代理，请按 [部署与更新说明](docs/v0.3.0-部署与更新.md) 配置。

### 登录后怎么使用

1. **选择网络方式**：默认全部直连，添加代理不会自动启用。打开“设置 → 代理池 → 按操作选择线路”，分别为登录/提取、更新凭证、检测、签到、API 令牌、数据看板选择直连或指定节点；在“签到管理”可以逐账号或逐计划指定签到线路。
2. **添加账号**：到“凭证提取”添加账密账号，或使用 Session 导入功能填写 `session` 与 `api_user`。任务状态在“执行队列”查看。
3. **安排签到**：到“签到管理”查看或创建计划、选择账号并启用。签到结果在“运行日志”和账号明细中查看。
4. **配置备份**：进入“设置 → 远程自动备份”，填写 OSS 或 SSH/SFTP 配置，保存后测试连接。先执行一次“立即备份”，确认成功后开启总开关和计划。详见 [远程备份说明](docs/远程自动备份.md)。
5. **设置日志保留**：在“运行日志 → 日志保留”调整保留天数和自动清理间隔；备份日志可按“备份”分类筛选，并一起清理。

### Cloudflare Tunnel 反代

Tunnel 的服务地址可以保持 `http://127.0.0.1:8001`（端口使用实际应用端口）。v0.6.1 支持自动识别本机 cloudflared 的 HTTPS 转发，登录、来源校验和 Secure Cookie 会使用浏览器实际的 HTTPS 域名。

如果旧版仍显示“需要安全连接”，先在 `.env` 设置实际公网 HTTPS 的 `APP_PUBLIC_URL`，保持 `APP_ENABLE_HTTPS_PROXY=0`，然后重新创建 app 容器，再从网页升级。完整步骤与独立容器代理配置见 [Cloudflare Tunnel 说明](docs/Cloudflare-Tunnel.md)。

### 修改管理员密码

已登录时，在 **设置 → 管理员密码** 输入新密码，点击“保存新密码并退出”。无需原密码，支持 5–1024 个字符及纯数字。保存后立即生效，所有旧登录会话退出；重新登录即可，服务不需要重启。

忘记密码、无法进入网页时，在项目部署目录的交互式 SSH 终端运行：

```bash
sudo bash scripts/reset-password.sh
```

终端重置同样接受至少 5 个字符。它使用当前 app 的实际镜像，安全读取两次新密码，更新密码后重新创建 app 容器。主加密密钥、业务账号和数据保留。输入中断或不一致时会给出明确提示。网页设置的新密码不会明文写入部署信息.txt，旧的初始密码记录不再代表当前密码。

### 以后怎么更新

优先在网页打开“设置 → 版本更新”，点击“检测版本”，确认后更新。默认仓库是 `a06342637/anyqiandao`，也可自定义可信仓库。程序会先构建，再备份源码、数据与密钥，切换后检查健康，失败自动回滚。

升级到 v0.6.1 后，旧并发设置统一为 1，已有代理节点保留，所有操作默认直连。需要代理的操作请在“设置 → 代理池”明确选择；签到线路优先级为“计划指定 → 账号指定 → 签到默认线路”。指定代理最多进行 5 次网络尝试，均失败后直连替补一次。凭证错误、人工验证和已发出但结果不明的签到会停止，避免重复提交。

小服务器的 app 容器默认限制为 640MB 内存、1GB 内存与 Swap 总量、1 核 CPU。1GB 机器建议配置至少 1GB Swap，使用 `free -h` 检查；机器没有 Swap 时，容器的 Swap 上限不会凭空增加可用内存。所有任务逐个执行，可用内存不足时队列显示等待原因并在资源释放后继续。需要调整容器限制时，在 `.env` 设置 `APP_MEMORY_LIMIT`、`APP_MEMORY_SWAP_LIMIT`、`APP_CPU_LIMIT` 后重新创建 app 容器。

若提示更新执行器离线，在服务器运行：

```bash
cd /opt/any-signin-assistant
bash scripts/install-updater.sh
systemctl status any-signin-assistant-updater --no-pager
```

推荐使用运行 systemd 的完整 Linux 服务器。NAS、容器内等没有 systemd 的环境，需要按 [部署与更新说明](docs/v0.3.0-部署与更新.md) 单独安排更新执行器。

需要手动升级时，从 [Releases](https://github.com/a06342637/anyqiandao/releases) 下载发布包，按 [升级与回滚说明](docs/升级与回滚.md) 操作。必须保留原目录中的 `.env`、`data/`、`secrets/`、`backups/`、`updates/` 和 `部署信息.txt`，不要用“先删整个目录再上传”的方式更新。

### 常见问题

- **网页打不开**：先看容器是否 `healthy`，再核对 `.env` 中的 `APP_PUBLIC_URL`、`APP_PORT` 和安全组。Docker 发布端口可能绕过部分 UFW 规则，限制来源 IP 时优先使用云安全组或 Docker 专用防火墙规则。
- **提示需要安全连接**：公网 HTTP 已禁止登录。无域名时将访问地址配置为本机地址，并使用 SSH 隧道；有域名时配置 HTTPS。已有实例的域名切换方法见 [安全与隐私说明](docs/安全与隐私.md)。
- **构建下载失败**：检查服务器能否访问 GitHub、Docker 镜像源和系统软件源，修复网络后在原目录重新运行 `bash scripts/deploy.sh`。
- **提示配置或密钥缺失**：恢复与现有数据库匹配的原文件，不能删除数据库或重新生成密钥来修复。
- **不执行签到**：检查代理/直连设置、队列是否暂停、计划是否启用，以及账号凭证是否有效。

更详细的说明见 [TXT 部署教程](部署教程.txt)、[使用说明](使用说明.txt) 和 [升级与回滚说明](docs/升级与回滚.md)。

## 安全和数据

- AES-256-GCM 字段加密、Argon2 管理密码哈希、HttpOnly/SameSite Cookie、CSRF 与来源校验。
- 数据库与密钥不匹配时拒绝启动，不生成替换密钥。账号密码加密保存，用于 Cookie 失效后的自动重新登录。
- 浏览器会话临时隔离；签到发送后结果不明时，不自动重发。
- 网站数据查询只使用当前凭证，不登录或签到；结果加密暂存 10 分钟，令牌不会写入日志、浏览器本地存储或 JSON 备份。
- 阻止网站页面自发的签到请求，检测、令牌查询和凭证修复不会顺带领取，也不改写最近签到任务时间。独立保存每日余额观察与明确回执，今日已有依据时只刷新余额、不重复提交签到。
- 首次读取或跨日没有当日基线时不凭空补算；消耗数据缺失、计数重置和跨日回执保守处理。邀请划转恰好为 $25 时仅凭余额无法完全区分，详情保留在日志中。
- 容器非 root、只读根目录、资源限制与日志轮换。Docker 更新权限不交给 Web 容器。
- 网页备份为 JSON，远程备份为 ZIP，无需额外密码。文件包含账号与凭证，请私密保存；传输仍使用 HTTPS/SSH，服务器中的凭证继续加密保存。
- 不上传任意脚本、不执行用户输入的 shell 命令、不修改 GitHub Secrets。在线更新只使用管理员明确选择的可信项目发布源。

内置签到函数来自固定提交 `9f1394d0f5ccf687eb21a0307ef4ccd4e71ecd3a` 的 [millylee/anyrouter-check-in](https://github.com/millylee/anyrouter-check-in)，BSD-2-Clause，来源和许可证见 `app/vendor/`。它不是本助手的程序更新仓库。

数据库版本：9，新增账号/计划签到线路；旧并发配置自动改为全局 1，旧代理池模式迁移为默认直连。保留账号独立加密每日签到依据与固定奖励字段，保留短期加密网站查询缓存；原账号、凭证和历史记录无损保留。旧记录缺少的消耗不补造。删除队列任务保留日志及统计；清理签到明细会减少历史统计，但不清除每日签到依据和账号最近任务时间。备份恢复支持每日依据，并按 api_user 隔离身份。签到时间和间隔仅在签到管理设置。
