# 升级与回滚

只操作 `/opt/any-signin-assistant` 与 `any-signin-assistant` Compose 项目，禁止 Docker 全局清理、删除其他容器或修改磁盘挂载。

## 升级

v0.3.0 起优先使用设置中的「版本更新」。默认使用 a06342637/anyqiandao 发布仓库，也可自定义；完整流程与新服务器交互式部署见 `v0.3.0-部署与更新.md`。在线更新会完整备份并在失败时自动回滚。以下是手动维护流程。

1. 网页暂停队列，等运行中的任务结束。不要强杀正在提交签到的进程。
2. 执行 `bash scripts/backup.sh`。数据库使用 SQLite backup API 获得一致性快照，并做完整性校验；保存在 `backups/<UTC时间>/`。原运行镜像会标记为 `any-signin-assistant:rollback-<UTC时间>`。
3. 新备份包含 `secrets/app.key`、`secrets/admin.hash` 与 `app.env`；较旧备份可能没有密钥，应补充独立离线备份。不要放在公开网盘、镜像或 Git 中。
4. 另存原版本源码，再覆盖应用源代码；保留 `.env`、`data/`、`secrets/`、`backups/` 和 `updates/`。先阅读新版本迁移说明。
5. 执行 `bash scripts/deploy.sh`。已有数据库时会再检查暂停状态并备份；不会自动替换丢失密钥。
6. 检查本项目容器健康、HTTPS、账号数量与导出，再从网页恢复队列。

## 回滚

回滚需要旧镜像、与该镜像迁移版本匹配的数据库快照，以及与数据库匹配的原始密钥。仅回退代码可能无法读取更新后的数据库。

1. 只停止本项目后端：`docker compose -p any-signin-assistant stop app`。
2. 先另存当前的 `data/assistant.sqlite3`，如有同名 `-wal` 和 `-shm` 文件也一并留档。
3. 从指定的 `backups/<UTC时间>/assistant.sqlite3` 恢复到 `data/assistant.sqlite3`，设置所有者为 `10001:10001`、权限 `600`。应用停止后，移除当前目录中该数据库对应的陈旧 `assistant.sqlite3-wal`、`assistant.sqlite3-shm`，不要操作其他文件。
4. 确认 `secrets/app.key` 与快照匹配，不要生成新密钥。升级不应修改主密钥。
5. 将 `.env` 中 `APP_IMAGE` 设置为备份的 `rollback-image.txt` 指定镜像标签。
6. 恢复匹配的旧源码和 Compose 配置，执行 `docker compose -p any-signin-assistant up -d --no-build --wait app`。原 Caddy 容器与证书卷保持不变。
7. 检查账号、凭证与队列。对于中断前可能已经提交的签到，先到原网站确认，不要盲目补发。

在线更新备份的配置文件名为 `.env`，源码在 `source.tar.gz`；手工恢复后核对 `meta` 表中的 `maintenance` 和 `queue_paused`，确认服务健康再解除维护。不要在程序运行时复制覆盖数据库。

不要运行 `down -v` 或任何全局 prune。备份文件不会自动删除，由管理员根据实际磁盘空间及离线备份情况管理。

## 本版本迁移

- 应用版本 0.3.4，数据库版本 7。版本 7 新增 console_results 表，短期加密保存网站看板与令牌查询结果；不修改原账号、凭证或签到历史。旧部署的队列保留天数继承原日志保留天数，其他清理策略不变。
- Session 导入账号用缺省密码标识凭证来源，兼容备份恢复；失效后停止定时重试，等待手动更新。同一账号补充真实用户名和密码后可显式改为账密模式。
- 版本 6 新增签到前后累计消耗字段，旧记录保留原值，不补造缺失数据；备份恢复兼容新旧记录。
- 数据库版本 5 新增任务隐藏标记，删除队列任务时保留原有日志及统计；旧设置的签到并发默认为 1。
- 数据库版本 1 建立账号、队列、代理、计划、日志和会话表。
- 数据库版本 2 新增短期一次性导出请求表和账号查询索引。
- 数据库版本 3 新增备注、顺序、日志分类和签到统计。
- 数据库版本 4 为签到统计记录余额来源，旧数据标为历史缓存，新记录使用实时签到前后值。
- 已有数据库先验证加密密钥，验证成功后才迁移。高于本程序的数据库版本拒绝启动。
