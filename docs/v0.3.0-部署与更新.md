# 部署与在线更新（v0.3.7）

## 可选 HTTPS 部署

本项目可通过 Caddy 提供 HTTPS：设置自己的 APP_DOMAIN 和 APP_PUBLIC_URL，启用 https profile。
Caddy 监听 80/443，通过本项目 Docker 网络反代 app:8000，并自动申请和续期证书。
证书保存在 caddy_data 卷中。不要删除证书卷；服务器地址和域名以自己的部署配置为准。

默认更新源为 a06342637/anyqiandao，可在设置中自定义。

## 新服务器：IP + 端口

推荐 Ubuntu 22.04+ / Debian 12+、至少 2GB 内存及 6GB 可用空间。缺少的 Python 3、Docker Engine 和 Compose 由部署脚本自动安装；已有 Docker 不会被卸载或替换，已运行的 Docker 不会被重启。在线更新执行器使用 systemd。其他 Linux 需预先安装 Docker、Compose、Python 3.10+ 和 flock。完整的新手步骤见根目录 `部署教程.txt`。

```bash
sudo -i
cd /opt/any-signin-assistant
bash scripts/deploy.sh
```

首次部署依次询问：

1. **端口**：回车随机选择一个当前空闲端口，显式输入时检查范围和占用。
2. **用户名**：回车默认 `admin`；可使用 1–64 位字母、数字及 `_.@-`。
3. **密码**：回车使用默认随机强密码；自定义 12–1024 位，不回显，不写入构建日志。

程序自动获取服务器 IP，并写入 `.env`、`secrets/` 和私密文件 `部署信息.txt`。最终打印 `http://IP:端口`。密码只保存在私密部署信息文件与加密哈希文件中，服务器 SSH 密码不写入本项目。

新部署默认不启用 Caddy、不申请证书、不占用 80/443。请自行开放所选端口对应的防火墙或安全组规则；脚本不会修改全局防火墙。

HTTP 不加密，建议只在可信网络初始化，随后配置自己的 HTTPS 反向代理。访问凭证管理页面时，尽量不要长期使用公网明文 HTTP。

重复运行部署脚本属于升级：不会重新询问或覆盖已有端口、用户名、密码及密钥。必须将源码覆盖到原部署目录并保留 `.env`、`secrets/`、`data/`、`backups/`、`updates/` 和 `部署信息.txt`；不要先删除整个目录。脚本拒绝从新目录接管已有容器，并与在线更新共用互斥锁。

手动部署先构建再备份，健康后恢复原队列状态；备份失败会尝试恢复队列，切换后未健康则保持暂停。手动覆盖前的旧源码无法凭空还原，需要完整源码自动回滚时使用发布包更新流程。自动安装只从发行版和 Docker 官方软件源获取软件，不运行远程 `curl | sh` 安装脚本。

可用于无人值守部署的环境变量：`APP_INSTALL_PORT`、`APP_INSTALL_USERNAME`、`APP_INSTALL_PASSWORD`、`APP_INSTALL_HOST`。密码不要放进 shell 历史或公开 CI 日志。检测公网 IP 失败时，可显式设置 `APP_INSTALL_HOST`。

## 自己配置反向代理

例如，外部 Caddy/Nginx 把 `https://your.example` 转发到 `http://127.0.0.1:所选端口`。完成后修改 `.env`：

```dotenv
APP_PUBLIC_URL=https://your.example
APP_BIND_HOST=127.0.0.1
APP_ENABLE_HTTPS_PROXY=0
APP_ALLOW_INSECURE_HTTP=0
```

再运行：

```bash
docker compose -p any-signin-assistant up -d --no-build --wait app
```

必须同步修改 `APP_PUBLIC_URL`，否则浏览器来源校验会拒绝写操作；切换 HTTPS 后 Cookie 自动带 Secure 标记，重新登录即可。如果反代本身在另外一个容器中，请使用其可达的应用网络地址，不要把该容器内部的 `127.0.0.1` 当成宿主机。

兼容旧的托管 HTTPS 新部署：`bash scripts/deploy.sh https://your.example`。仅在确实要让本项目 Caddy 管理 80/443 和证书时使用。

## 设置 → 版本更新

设置页面显示当前版本、远程版本、上次检测时间、更新进度和结果，支持强制更新。

**当前工程没有 Git 远程发布仓库，因此不会预填或伪造远程版本。** `millylee/anyrouter-check-in` 只是内置签到函数的上游，不是本应用源码的更新源，不能用于更新本程序。

配置你自己维护或信任的**本项目公开 GitHub Releases 仓库**，格式为 `用户名/仓库名`。暂不支持需要 GitHub Token 的私有发布仓库。保存后点击「检测版本」；一分钟内重复检测使用缓存，避免触发 GitHub 限流。

正式发布的步骤：

1. 更新 `VERSION`、`frontend/package.json` 和更新日志，并执行测试。
2. 执行 `python3 scripts/build_release.py`，在 `.release/` 生成 `any-signin-assistant-v版本.tar.gz` 与 `release.json`。
3. 创建对应 `v主.次.修订` 的 GitHub Release，并上传这两个附件。不支持草稿或预发布。
4. 在设置中配置这个仓库，检测并更新。

发布打包使用源码白名单，不包含 `.env`、密钥、数据库、备份、更新工作目录、开发缓存或 `tools/` 验收资料。

更新器重新确认版本和发布来源，校验 SHA-256、文件大小、项目标记、解压路径及本地源码改动。强制更新允许覆盖源码改动或重装同版本，但不允许在线降级，不覆盖运行配置与业务数据。

更新顺序：下载校验 → 构建新镜像（原服务仍可用）→ 等待任务完成 → 暂停本项目应用 → 完整备份 → 切换版本 → 检查健康和数据数量 → 恢复原队列状态。切换期间拒绝写操作，任务不会被重复签到。

新版本失败会自动恢复原源码、数据库和配置；主机中断后，执行器启动时会检测并恢复未完成的更新。完整备份保存在 `backups/update-时间-编号/`，包含原密钥，必须私密保存。更新不清理备份、Docker 全局镜像或其他容器。

页面会跨应用重启持续跟踪，成功后自动刷新。更新窗口关闭后，后台仍会继续，可重新打开设置查看持久化进度。

## 执行器和故障检查

Web 容器不挂载 Docker socket。独立 systemd 执行器只处理本项目的结构化请求，通过请求目录和只读状态目录通信。

```bash
sudo bash scripts/install-updater.sh
systemctl status any-signin-assistant-updater.service
journalctl -u any-signin-assistant-updater.service -n 60 --no-pager
docker compose -p any-signin-assistant ps
curl -fsS http://127.0.0.1:18780/healthz
```

端口命令请按部署实际值调整。构建详情位于 `updates/work/任务编号/update.log`。无 systemd 时，可以用受保护的进程管理器运行 `/usr/local/lib/any-signin-assistant-updater/update_runner.py --root 项目目录`；执行器离线时设置页会明确提示，而不是假装更新成功。

## 没有 GitHub 发布仓库时手动更新

不要把签到脚本上游当作此助手的更新源。未配置发布仓库时，设置页明确显示「未配置更新源」，不会假装检测到最新版本。可将源码发布到自己维护的公开 GitHub 仓库，并上传构建生成的源码包和 `release.json`；随后在设置中填写 `用户名/仓库名`。

离线/本地包升级也使用同一套校验、备份、健康检查和回滚流程。将 `scripts/build_release.py` 输出的源码包与 `release.json` 上传到私密目录后执行：

```bash
sudo systemctl stop any-signin-assistant-updater.service
sudo python3 scripts/update_runner.py --root /opt/any-signin-assistant \
  --install-archive /私密目录/any-signin-assistant-v0.3.4.tar.gz \
  --manifest /私密目录/release.json
sudo bash scripts/install-updater.sh
```

路径和版本应替换为实际值。旧于 v0.3.1 的实例须从已验证的新版源码中运行这个执行器；不能先覆盖运行目录再假称已经备份旧源码。存在本地源码修改时默认拒绝覆盖，明确需要覆盖再追加 `--force`。不允许降级。失败时查看设置中的更新进度及保留的完整备份，不要清空数据库或重新生成密钥。

## 站点外观

设置 → 站点外观中可修改网站名称（1–40 字）和图标文字（1–2 字），保存后同步更新左上角、登录页、页脚、浏览器标签标题及 favicon。名称只是显示名称，不改变管理员用户名或域名，且随 JSON 备份恢复。

## 数据口径

v0.3.0 在同一次浏览器会话内读取签到前、签到后的实时余额，列表展示前后数值和新增金额。仪表盘只累计「签到成功且前后都读取成功」的正差额；已签过、失败、缺少余额或负差额不计入新增。

旧版记录使用缓存余额作为基数，无法事后可靠修正。升级保留这些记录和次数，标为「历史记录」，不混入实时确认的新增余额。统计金额仍可能受到两次读取之间账号消耗或充值的影响，是余额差统计，不是网站发放明细账。

签到遇到失效 Cookie 时，在同一个任务中记录原因、用已保存密码重新提取，再继续签到；不会循环重登，也不会因网络异常误判 Cookie 失效。
