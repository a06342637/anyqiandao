# 安全与隐私

## 登录前可见范围

未登录仅返回独立登录页，可见的是固定的介绍文案和装饰性周历，不读取实际签到情况。账号、凭证、代理、计划、运行日志、备份配置、更新状态、自定义站点名称和业务前端资源均要求有效会话。未登录调用私有接口统一返回 401。健康接口对外只返回是否健康；容器和宿主机的本地更新探针保留版本信息，供旧版一键更新核验。

退出登录会在服务端撤销会话、删除 Cookie 并清理浏览器站点缓存。多个已打开的页面会同步退出；从浏览器返回缓存页面时重新验证登录。

## 传输和保存

- 公网管理访问必须使用 HTTPS。来自本机、Docker 宿主网关或显式可信代理的 HTTPS 转发头可识别外部 TLS；公网客户端伪造转发头不会获得信任。
- 不带域名的首次部署默认只监听 `127.0.0.1`，通过 SSH 隧道访问；HTTPS 部署由内置 Caddy 终止 TLS，后端端口保持仅本机访问。
- 账号用户名、密码、Cookie、代理凭证及远程备份配置使用 AES-256-GCM 加密保存，管理员密码使用 Argon2 哈希。原始加密密钥单独存放在受限权限文件中。
- OSS 使用 HTTPS 和官方 V4 签名，SFTP 使用 SSH 加密及主机指纹校验。SSH 目标改变时需重新输入凭证。
- 登录 Cookie 使用 HttpOnly、SameSite=Strict；HTTPS 下启用 Secure。写接口校验 CSRF，同源检查也覆盖已登录读取。
- 复制账号或导出上游需要的 Session 配置属于登录后的显式操作，浏览器可获得相应明文内容；传输通过 HTTPS/SSH 隧道保护。请保管好自己下载或复制的数据。

使用外部反向代理时，必须正确终止 HTTPS、覆写转发协议头，并把应用后端限制在可信网络或本机。不要把明文后端直接暴露到公网。

Cloudflare Tunnel 回源为 HTTP 时，程序会统一还原外部 HTTPS 来源，用于登录、CSRF 和 Secure Cookie。详细配置见 [Cloudflare Tunnel 说明](Cloudflare-Tunnel.md)。

## 备份与恢复

网页导出 JSON，远程备份生成 ZIP，备份和恢复均不设置额外密码。备份内容包括账号和凭证，请保存在自己的私有存储中。登录保护、HTTPS/SSH 传输、服务器内 AES-256-GCM 凭证加密仍然生效。

已有 v0.5.0 的 ASB 加密备份可使用 `scripts/decrypt_backup.py` 离线转换，再导入 JSON 或 ZIP。该兼容工具只处理旧文件，仍需要旧文件原密码。正常备份和恢复界面不再显示密码输入框。

服务器升级/回滚备份仍保存在受限权限的本机目录中。

## 升级提醒

本版本保留现有账号、主加密密钥、管理员和 HTTPS 配置，支持从 v0.4.1 点击一键更新。更新器的本地健康检查兼容保留。

已有公网 HTTP 部署升级后必须改用 HTTPS，或设置本机访问地址并通过 SSH 隧道连接。此前被 v0.5.0 暂停的定时备份，升级后可直接重新开启总开关，不需要备份密码。

## 源码范围

源码仓库和发布包不应包含 `.env`、部署信息、数据库、密钥、实际账号、备份文件或个人运维脚本。示例只使用保留的示例地址和合成数据。`tools/verify_source_privacy.py` 会检查已跟踪文件，发布流程同时检查登录隔离、备份恢复、解压权限和容器启动。

本地依赖、构建产物和测试临时目录不属于交付源码。历史中已公开的数据无法通过删除当前文件撤回，遇到真实密码或私钥泄露应及时轮换对应凭证。
