# 安全与隐私

## 登录前可见范围

未登录仅返回独立登录页。账号、凭证、代理、计划、运行日志、备份配置、更新状态、自定义站点名称和业务前端资源均要求有效会话。未登录调用私有接口统一返回 401。健康接口对外只返回是否健康；容器和宿主机的本地更新探针保留版本信息，供旧版一键更新核验。

退出登录会在服务端撤销会话、删除 Cookie 并清理浏览器站点缓存。多个已打开的页面会同步退出；从浏览器返回缓存页面时重新验证登录。

## 传输和保存

- 公网管理访问必须使用 HTTPS。仅伪造 `X-Forwarded-Proto` 无法把 HTTP 部署变成可信 HTTPS 部署。
- 不带域名的首次部署默认只监听 `127.0.0.1`，通过 SSH 隧道访问；HTTPS 部署由内置 Caddy 终止 TLS，后端端口保持仅本机访问。
- 账号用户名、密码、Cookie、代理凭证及远程备份配置使用 AES-256-GCM 加密保存，管理员密码使用 Argon2 哈希。原始加密密钥单独存放在受限权限文件中。
- OSS 使用 HTTPS 和官方 V4 签名，SFTP 使用 SSH 加密及主机指纹校验。SSH 目标改变时需重新输入凭证。
- 登录 Cookie 使用 HttpOnly、SameSite=Strict；HTTPS 下启用 Secure。写接口校验 CSRF，同源检查也覆盖已登录读取。
- 复制账号或导出上游需要的 Session 配置属于登录后的显式操作，浏览器可获得相应明文内容；传输通过 HTTPS/SSH 隧道保护。请保管好自己下载或复制的数据。

使用外部反向代理时，必须正确终止 HTTPS、覆写转发协议头，并把应用后端限制在可信网络或本机。不要把明文后端直接暴露到公网。

## 加密备份

网页导出和远程备份生成 `.asb` 文件。采用 scrypt 派生独立密码密钥及 AES-256-GCM，每份文件随机生成盐和 nonce，并校验认证标签。密码错误或文件被篡改时，不恢复任何数据。备份密码不会放入备份文件，远程备份密码只加密保存在数据库中。

恢复 ASB 时输入生成该备份时使用的密码。更改远程备份密码只影响之后的文件，旧备份仍使用旧密码；丢失密码无法恢复。旧版 JSON/ZIP 可以导入，但新版本不再生成未加密的网页/远程备份。

完整备份需要离线恢复时，在安装了项目依赖的电脑上执行：

```bash
python scripts/decrypt_backup.py 你的备份.asb --output restored.zip
```

密码在终端输入，不作为命令行参数保存。远程备份解密后是 ZIP；网页手动导出的备份解密后是 JSON，可将输出文件命名为 `restored.json`。解密文件包含敏感数据，请私密保存，使用后及时清理。

服务器升级/回滚备份仍由原管理脚本保存到仅管理员可访问的本机目录，包含恢复必需的原密钥。不要将这些服务器运维备份上传到源码仓库。

## 升级提醒

本版本保留现有账号、主加密密钥、管理员和 HTTPS 配置，支持从 v0.4.1 点击一键更新。更新器的本地健康检查兼容保留。

已有公网 HTTP 部署升级后必须改用 HTTPS，或设置本机访问地址并通过 SSH 隧道连接。旧的自动备份若未设置独立备份密码，升级后暂停定时备份并记录提醒；填写密码、保存并测试后重新启用。

## 源码范围

源码仓库和发布包不应包含 `.env`、部署信息、数据库、密钥、实际账号、备份文件或个人运维脚本。示例只使用保留的示例地址和合成数据。`tools/verify_source_privacy.py` 会检查已跟踪文件，发布流程同时检查登录隔离、加密备份、解压权限和容器启动。

本地依赖、构建产物和测试临时目录不属于交付源码。历史中已公开的数据无法通过删除当前文件撤回，遇到真实密码或私钥泄露应及时轮换对应凭证。
