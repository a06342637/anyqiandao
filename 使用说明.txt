any签到助手 v0.4.1 使用说明

部署入口：将项目源码上传到 Ubuntu 22.04+ / Debian 12+，在项目目录运行 sudo bash scripts/deploy.sh。
脚本自动安装缺少的 Docker / Compose / Python。端口回车随机空闲值，用户名回车 admin，密码回车生成随机强密码。
重复部署保留服务器原配置、账号和密钥；更新时不要删除或覆盖 .env、data、secrets、backups、updates。
详细上传、访问、密码查看、更新与排错步骤见同目录「部署教程.txt」。
顶部管理账号、有效凭证、等待执行和下一次计划签到四张卡片仅在仪表盘显示，其他页面直接展示各自内容。

一、进入工作空间
使用部署时设置的管理员账号和密码登录。新部署用户名默认 admin，密码留空会生成随机强密码，保存在服务器项目目录的「部署信息.txt」。已有部署升级不修改账号密码。
打开页面、刷新页面或重新登录时默认进入仪表盘。左侧依次为仪表盘、凭证提取、账号列表、签到管理、运行日志、执行队列；设置在侧栏最底部，手机上使用右上角设置按钮。
设置 → 站点外观：可修改网站名称与图标文字，左上角、登录页、页脚和浏览器标签同步更新；不修改管理员账号。

二、提取与自动签到
先在设置中配置代理，或明确选择直连。单账号、逐行「账号----密码」或 CSV 都可导入；复杂密码建议 CSV，以免分隔符歧义。
提取任务会保存加密密码和完整凭证。开启自动签到时，提取成功自动加入默认计划并签到一次。
没有账号密码时，选择「Session 导入」：单个填写 session 和数字 api_user，或批量粘贴一行一组「session----api_user」；也支持 [{"cookies":{"session":"凭证值"},"api_user":"123"}]，可加 username 作为显示名称。凭证加密保存，重复 api_user 或已有账号名称会跳过，不覆盖原账号。
这类账号标记为「Session 手动导入 · 仅签到」，不尝试自动登录。开启「提取后自动签到」时，导入后签到一次并加入默认计划；关闭时仅保存。失效后保留账号并跳过后续定时重试；到账号列表点击「更新凭证」，填写相同 api_user 的新 session 后恢复使用。更新也遵循自动签到开关。
执行队列位于运行日志下方，顶部任务状态也可点击直达。普通队列与签到队列分别支持 1–5 并发，保存后即时生效；签到默认串行，多个计划同时到期也依次执行。同账号跨队列不会同时运行。暂停后已有任务继续完成，代理测试仍可执行。支持刷新、筛选、分页及停止并删除任务，删除后保留账号、日志和签到统计。

已添加账号不会重复添加或覆盖密码；批量和 CSV 会跳过并提示。重新提取或修改密码请在账号列表操作。每次提取、签到以及代理切换会在日志标明直连或代理名称与地址，不记录密码或 Cookie。

签到间隔与执行规则统一在签到管理设置；运行设置不再提供默认计划间隔，也不会在保存时重置已有计划。Cookie 失效时自动用保存的密码重新提取一次并继续本轮签到，遇到人工验证则停止并在日志提示。
操作结果在页面底部居中提示，并写入日志。任务未完成时显示实际进度，不把「已入队」当成执行成功。

三、账号列表
从序号、账号开始，按凭证时间、余额和账号操作分区排列；桌面显示表格，平板与手机按宽度调整为卡片。支持多选、分页、跨页选择、备注、编辑和拖拽排序。拖动左侧专用把手排序；也可聚焦把手后按 Alt+上/下。筛选状态下不进行拖拽排序。
修改账密账号的登录名称会作废旧凭证，避免把旧账号 Cookie 用在新账号上；Session 账号仅修改显示名称时保留凭证。历史统计保留。只修改密码或备注不会清除现有凭证。账号有待执行/运行任务时不能修改账号密码。
勾选账号后，「仅重提失效」只重新登录已标记失效且保存密码的账号；「全部重提」重新登录所选有密码的账号，包括仍有效的凭证。Session 账号不参加自动重提。
「账密账号失效时自动重提」默认勾选：点击「检测并修复」会检查所选账号，发现失效时用保存的密码重提一次并复查；取消勾选则仅检测。Session 账号等待手动更新。网络故障或验证码不会触发重登。
检测读取最新有效性与余额；余额旁边的刷新执行同样的实时检测与修复，不会触发签到。
「余额」区域仅展示当前余额和「上次签到」时间（北京时间，即最近一次签到任务时间），不再混入「结果待确认」「已签到」或新增金额。点击「明细日志」查看签到前后余额、期间消耗及网站回执；查询 API 令牌、数据看板或刷新余额不会修改这个任务时间。
每日签到按北京时间 00:00 开始的新一天判定：余额变化加回期间消耗后正好增加 $25，或网站明确返回已签到/签到成功，即保留本日依据。余额减少视为消费，不清除已确认的当天状态；其他金额增加不直接算签到。已有今日依据时只刷新余额，不重复提交领取。
首次读取或跨日没有当日基线时不补造签到；消耗数据不完整或重置时不强行推算。邀请人划转恰好为 $25 与签到在余额上无法完全区分，此类少见情况需结合网站明细核实。
新确认签到奖励固定计 $25，邀请划转不作为额外签到奖励；已签过、待确认不重复累计。每日依据独立加密保存，清理日志或明细不会丢失，备份恢复会带上并校验账号身份。
日、近 7 天和近 30 天统计统一按北京时间 00:00 划日，修改显示时区不会改变统计范围。领取前还会利用同一浏览器会话的最新余额复核：若已观察到今天的 $25 到账，直接记为已签过，不再发送领取请求。
余额或消耗暂时读不全时，保留上一份完整观察和账号已知余额，之后读全再核对；不会拼接不同请求的数据。页面读取中、读取失败和真正没有账号分别展示，切换统计范围不会沿用上一个范围的错误提示。
恢复备份时会比较最新余额观察时间，避免旧备份把新余额覆盖回去；同一账号同一天的已确认依据会合并保留，不会被较新的未确认快照清除。
复制按钮分为「账密」和「凭证」两组：可分别复制账号、密码、账号----密码、session、api_user，或复制适配 ANYROUTER_ACCOUNTS 的单行 JSON 数组。大量数据可下载配置。
账号操作新增「数据看板」和「API 令牌」，点击后只为当前账号加载。看板显示网站余额、累计消耗、累计请求以及近 24 小时/7 天/30 天的使用量、趋势与模型分布；平均 RPM/TPM 是所选时间范围内的平均值，不代表网站限流上限。
API 令牌窗口分页展示网站已创建的令牌，可复制完整密钥，并查看状态、已用/剩余额度、有效期、分组、模型与 IP 限制。无限令牌仍受账号余额限制；网站没有返回完整密钥时不伪造可复制密钥。
查询进入普通队列，同账号始终串行；不自动登录、不签到、不创建或修改令牌，队列暂停时需先继续队列。接口不可用会明确提示。查询结果加密暂存 10 分钟，过期后重新加载；密钥不写日志、浏览器本地存储或 JSON 备份。

四、签到管理与仪表盘
创建计划时选定账号和间隔，可暂停、继续、立即执行或编辑。支持分页及刷新。
Cookie 失效时，在同一签到任务中记录失效原因、自动重提和继续签到的过程。没有保存密码、未开启自动重提或新凭证仍失效时明确报错，不无限循环登录。结果不确定时不重复提交。
仪表盘按今天、近 7 天、近 30 天展示新增余额、成功/已签/失败次数、确认成功率、总余额和账号明细。中断/超时导致的结果待确认单独展示，不当成成功或失败。总数、图表和账号明细采用一致的数据库快照与时区，未来时间的记录不提前累计。
v0.3.0 前的统计基于旧缓存，保留次数及原记录但不混入实时确认的新增金额。v0.3.3 在消耗计数完整且未回退时，将两次读取间的消耗加回新增；期间充值仍可能影响余额差，它不是网站原始发放账单。
网站登录后会自动请求签到，助手会阻止这类页面自发请求，统一由签到任务领取。网站重复请求可能只返回 success=true 和空消息；这不代表新增。未观测到新增时，只有当前凭证提取后当天（按工作空间时区）已有真实到账记录才显示已签过，否则保留待确认，不自动重发。

五、设置、日志与备份
运行与日志：调整并行数、超时、间隔、时区、自动签到和 Cookie 自动重提。「日志保留」统一设置运行/账号日志、已结束队列、账号明细/签到统计的保留天数，以及每隔多少小时清理，并显示上次/下次执行时间。新部署默认分别为 7、7、90 天，每 24 小时清理；旧部署保留原设置，队列保留天数继承原日志设置。
运行日志、执行队列、仪表盘账号明细均提供「日志保留」入口。运行/账号日志与签到明细可跨页多选删除、全选当前筛选或按本机时区的截止时间清理；可从仪表盘「管理明细日志」管理全部签到明细，或打开单账号明细。
执行队列支持跨页多选、删除所选和清理已结束。删除选中的等待/运行任务会先取消并等待安全结束，已发出的签到请求不重复发送；清理已结束或自动清理不影响等待/运行任务。
日志清理保留账号、凭证、计划及等待/运行任务相关记录。队列记录删除不连带删除日志或统计；主动清理签到明细会同步减少相应历史统计，不重置账号最近签到状态。手动删除需要确认且不可撤销；「清理到期记录」只使用已经保存的策略。
代理池：支持 HTTP / SOCKS5 / SSH，整行粘贴识别配置，SSH 首次使用须确认指纹。不会在代理失败后偷偷切换到直连。
备份与恢复：一键下载 JSON，也可导入远程备份 ZIP，包含账号密码、凭证、备注、顺序、计划、代理、运行设置和签到统计。备份含明文秘密，请私密保存。恢复需要先暂停队列并等待任务结束，按账号合并，同一份备份重复恢复不会产生重复签到记录。
版本更新：默认使用 a06342637/anyqiandao 的 GitHub Releases，支持填写其他可信仓库或留空恢复默认。执行器离线时会明确提示。强制更新会先备份再覆盖本地源码；不覆盖密钥、账号和部署参数。

六、服务器和新部署
可选 HTTPS 部署：Caddy 自动申请/续期 Let's Encrypt 证书，并反代到 app:8000；宿主机应用端口为 127.0.0.1:18780。
新部署运行 sudo bash scripts/deploy.sh：询问端口（回车随机）、用户名（默认 admin）、密码（回车随机强密码），自动写配置后输出 http://IP:端口。新部署不默认配置反代或证书。
HTTP 不加密，请自行配置防火墙与 HTTPS 反代；切换域名后同步修改 APP_PUBLIC_URL 并重建本项目应用容器。
详细命令及在线发布方法见 docs/v0.3.0-部署与更新.md；手动恢复见 docs/升级与回滚.md。

不要把 .env、data、secrets、backups 或「部署信息.txt」上传到公共仓库。不要执行全局清理 Docker、重装 Docker、格式化磁盘或删除证书卷的命令。

七、远程自动备份
设置 → 远程自动备份：设置总开关、频率、时间和时区，选择应用数据包或完整备份。
支持阿里云 OSS 与 SSH/SFTP，可同时启用。填写目标后保存设置，再测试连接或浏览目录。
密码、AccessKey Secret、私钥留空表示保留已保存值；SFTP 首次认证成功后记住主机指纹。
立即备份不改变定时计划；服务停机错过计划时，恢复后只补做一次。
每个目标上传成功后，按保留份数清理本实例旧备份。关闭总开关不删除配置或远程文件。
运行日志 → 备份 可筛选成功、失败及清理结果；备份日志与其他运行日志共用“日志保留与自动清理”策略。
详情与恢复步骤见 docs/远程自动备份.md。
